# Editions: one engine, two games

The repository builds two games from one engine:

| | English edition (default) | Spanish edition |
|---|---|---|
| Practised language | American English (`en-US`) | Spanish, Mexican by default (`es-MX`) |
| Learner's language (help, glosses, interface) | Lithuanian | American English |
| Town | Maple Harbor | Puerto Colibrí |
| Course | English Master (fluent-steps) | Spanish Master English (later) |
| Build | `npm run build` | `VITE_EDITION=es npm run build` |
| Dev server | `npm run dev` | `VITE_EDITION=es npm run dev -- --port 8094` |

## How it works: the edition overlay

A build, a test run or a tool for the Spanish edition sees `src/editions/es/<path>` **instead of** `src/<path>`
wherever such a file exists. Everything else is shared. So the Spanish edition replaces data and language modules,
never the engine:

| Base file (English edition) | Spanish file | What it is |
|---|---|---|
| `src/edition.ts` | `src/editions/es/edition.ts` | the edition's profile: language tags, town, storage keys, the sims' learner |
| `src/convo/lang.ts` | `src/editions/es/convo/lang.ts` | the practised language's words for the engine: fillers, negation, yes/no answers, the words around an answer, learner slips, sound-alikes |
| `src/convo/slots.ts` | `src/editions/es/convo/slots.ts` | numbers, prices, times, days, dates, letters, names, digits |
| `src/convo/target.ts` | `src/editions/es/convo/target.ts` | noun phrases, agreement and values in the practised language, glossed in the learner's |
| `src/content/global.ts` | `src/editions/es/content/global.ts` | the skills every conversation has (repeat, slower, spell, thanks, bye…) |
| `src/content/merges.ts` | `src/editions/es/content/merges.ts` | the registered multiword units |
| `src/content/npcs.ts`, `locations.ts`, `voices.ts`, `ambient.ts` | same names | the cast, the places, the voices, the passers-by |
| `src/content/situations/index.ts` | `src/editions/es/content/situations/index.ts` | the conversations (generated by `tools/gen-index.ts`) |
| `src/generated/known-words.json`, `ipa-lexicon.json` | `src/editions/es/generated/…` | real words never "corrected", IPA |
| `src/ui/strings.ts` (empty) | `src/editions/es/ui/strings.ts` | the interface in English, by its Lithuanian original (src/ui/i18n.ts `L()`, `Lx()`) |
| `src/ui/lt.ts` | `src/editions/es/ui/lt.ts` | counts and labels |
| `src/ui/scene-files.ts` | `src/editions/es/ui/scene-files.ts` | the illustrated scenes (none yet) |
| `src/game/world/theme.ts` | `src/editions/es/game/world/theme.ts` | the town's look (docs/es/TOWN.md) |

The overlay is applied by `tools/edition-overlay.mjs`: the Vite plugin (`vite.config.ts`: dev server, build and the
tests) and a Node hook for the tools (`tools/edition-hook.mjs`). An edition file that imports its own base file gets
the base (the Spanish `npcs.ts` builds on Maple Harbor's).

Rules:
- **Engine code is shared.** When the Spanish edition needs the engine to behave differently, the difference goes
  into a language or data module (as a word list, a function or a theme switch) with the English edition's current
  behaviour as its English value. Never copy an engine module into `src/editions/`.
- **An edition file has the base file's exports**, with compatible types (TypeScript checks the importers against
  the base file only).
- New interface text goes through `L()` / `Lx()` with its English in `src/editions/es/ui/strings.ts`
  (`npx tsx tools/i18n-check.ts`).

## Commands

```sh
# the tests of both editions (vitest projects "en" and "es")
npx vitest run
npx vitest run --project es

# any tool on the Spanish edition: EDITION=es and the hook
EDITION=es npx tsx --import ./tools/edition-hook.mjs tools/check-content.ts            # all Spanish conversations
EDITION=es npx tsx --import ./tools/edition-hook.mjs tools/check-content.ts s72 --verbose
EDITION=es npx tsx --import ./tools/edition-hook.mjs tools/review.ts s72-cafe --seed=3   # read the sims
EDITION=es npx tsx --import ./tools/edition-hook.mjs tools/gen-index.ts                # after adding a file
EDITION=es npx tsx --import ./tools/edition-hook.mjs tools/build-vocab.ts              # after content changes

# the English edition, as always (no EDITION)
npx tsx tools/check-content.ts

# the English edition is unchanged by an engine change: record before, compare after (≈ 18 min)
npx tsx tools/fingerprint.ts --out=/tmp/before.json
npx tsx tools/fingerprint.ts --diff=/tmp/before.json      # "✓ identical"
```

## What the Spanish edition does differently (engine level)

- **Speech**: the recognizer and the browser voice use `es-MX` (`EDITION.target`).
- **Understanding**: accents folded ("café" = "cafe"); "por favor" removed like "please"; "no" + verb stays negated
  ("No quiero leche"), only a correction word after "No" makes it an answer plus a correction; learners' extra "yo",
  tú/usted and gender slips, ser/estar and spellings by sound are understood; Spanish numbers, pesos ("ochenta y cinco
  cincuenta", "15 mil", "veinte pesos de limón"), times ("cuarto para las ocho"), dates, Spanish letter names and
  phone numbers in pairs.
- **Composing**: Spanish articles and agreement ("una horchata chica", "dos lattes grandes", "el agua"), "a el" →
  "al", `{u:usted|t:tú}`, `{m:…|f:…}` in the Spanish text, pesos and Mexican clock times in what is shown and said.
- **Mexican or neutral**: a line may carry a neutral twin (`neutral:`); `setVariety("neutral")` (compose.ts) shows and
  voices the twins. The setting is the edition's (`puerto-colibri-variety` in localStorage).
- **Saves**: `puerto-colibri-progress-v1`, `puerto-colibri-cards-v1` (never Maple Harbor's).
- **Voices**: `audio-es/`, voice ids `es_<npcId>`, `es_coach_f` / `es_coach_m` (not recorded yet: the browser speaks).

## How the English edition is kept unchanged

- `tools/fingerprint.ts` records every NLU test's reading, every sim's whole transcript on 12 seeds, every corpus and
  held-out sentence's reading and every sentence the game can speak (with its random conversations), hashed per
  situation. The switch was made with it: identical before and after.
- The tests (`npx vitest run --project en`) and `npx tsx tools/check-content.ts` (0 errors, 0 warnings) as before.
- The English build's interface: `L()` returns the Lithuanian text itself; the theme's switches are off.
